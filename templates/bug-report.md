# Bug report template

> A good bug report lets anyone reproduce the problem on the first try, without asking a single question.

## [Short title: what is wrong, where]

**Severity:** critical / high / medium / low
- **Critical:** data loss, security issue, or the main flow is blocked for everyone.
- **High:** a core feature fails and there is no workaround.
- **Medium:** a feature fails but there is a workaround.
- **Low:** cosmetic or minor inconvenience.

**Environment:** app version and build, device, OS version, user role, network conditions.

### Steps to reproduce
1. ...
2. ...
3. ...

**Reproducible:** always / sometimes (x out of y tries) / once

### Expected result
What should happen, ideally quoting the acceptance criterion.

### Actual result
What happens instead. Include the exact error message.

### Evidence
Screenshots, screen recording, logs (with personal data removed).

### Notes
- Related story or test case: KEY-?? / QA-??
- First seen in version: ...
- Suspected cause (optional): ...
